# Chamilo LMS on Railway

Railway template for [Chamilo LMS](https://chamilo.org), the open-source e-learning platform (courses, learning paths, SCORM, exercises, gradebook, certificates).

## What it deploys

| Service | Source | Volume |
|---|---|---|
| **Chamilo** | this repo: [`Dockerfile`](Dockerfile) installs the official **Chamilo 3.0.2** release package (`chamilo-3.0.2.zip`, sha256-checked) on `php:8.4.27-apache-trixie` (pinned by digest), with the PHP extensions Chamilo asks for (pdo_mysql, intl, gd, zip, soap, ldap, exif, bcmath, opcache, APCu) | `/data`: `.env`, JWT keys, uploads (`var/upload`), themes and custom templates |
| **MariaDB** | `mariadb:11.4.13` (official image, pinned by digest) | `/var/lib/mysql` |

Chamilo publishes no Docker image of its own, so the image is built from the release package exactly as the [official install guide](https://github.com/chamilo/chamilo-lms#quick-install) describes.

## First boot

[`railway/start.sh`](railway/start.sh) runs Chamilo's own installer (the final step of the web wizard) on a local-only port before Apache starts, so the public URL never shows an open install wizard. It creates the administrator `admin` with the password in the `CHAMILO_ADMIN_PASSWORD` variable (generated by Railway), sets the portal URL to the service's Railway domain, turns off self-registration and switches Chamilo to production mode. The first boot takes about a minute.

On every boot it writes the database variables into `.env`, applies pending database migrations (this is how an update reaches an existing install) and starts Apache on `PORT` (8080). The health check is `/healthz.php`: 200 only when Chamilo is installed and its database answers.

## Variables

| Variable | Default | Notes |
|---|---|---|
| `CHAMILO_ADMIN_PASSWORD` | `${{secret(24,…)}}` | Password of the first administrator. Used only on the first boot: change it in Chamilo afterwards |
| `CHAMILO_ADMIN_USERNAME` | `admin` | Login of the first administrator (first boot only) |
| `CHAMILO_ADMIN_EMAIL` | empty → `admin@<your Railway domain>` | Email of the first administrator (first boot only) |
| `CHAMILO_PORTAL_NAME` | `Chamilo` | Portal name shown in the header (first boot only, then Administration → Configuration settings) |
| `DATABASE_HOST`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD` | references to the MariaDB service | Synced into `.env` on every boot |
| `PORT` | `8080` | Port Apache listens on |

Optional, not set by the template: `CHAMILO_URL` (portal URL used at the first install, defaults to `https://<RAILWAY_PUBLIC_DOMAIN>/`), `CHAMILO_LANGUAGE` (default `en_US`), `CHAMILO_ORGANIZATION`, `MAILER_DSN` / `MAILER_FROM_EMAIL` (mail settings used at the first install; afterwards set them in Administration → Configuration settings → Mail).

**Custom domain:** after adding one on Railway, change the portal URL in Administration → Configure access URLs.

## Updates

Railway notifies everyone who deployed this template when `main` changes. Each update bumps the Chamilo release (and the base image digests) in the `Dockerfile` and is described in [`CHANGELOG.md`](CHANGELOG.md), breaking changes first. On the next boot the start script applies Chamilo's database migrations. Back up the MariaDB volume before applying a major update.

## Run it locally

```sh
docker build -t chamilo-railway .
# then run it next to MariaDB with the variables above and a volume on /data
```
